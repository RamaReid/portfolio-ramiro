## Entrega concreta

Núcleo identificado, privacidad verificada si existe remoto, kit trasladado y acta de base con commit/rutas reales.

## Comprobación y cierre

- Git identifica dos destinos distintos y la privacidad del nuevo remoto se comprueba; no se afirma creación remota si falta autenticación.
- La copia del kit contiene todos sus enlaces y encargos; estado inicial IM-002 e IM-003 disponible.
- Verificar enlaces, rutas y estado documental/Git; no ejecutar tests de aplicación por cambios solo documentales.
- Registrar pruebas realmente realizadas y sus límites; el integrador cierra solo después de revisarlas.

## Entrada pendiente que no se debe inventar

Si el nombre de destino corresponde a otro proyecto, preparar la alternativa y preguntar ese nombre concreto. No adivinar un repositorio remoto.

## Informe de salida

Devolver archivos o parche y el informe según TRASPASO. Separar cambio local, commit, push, migración, servidor desplegado, frontend publicado y URL comprobada; usar «no realizado» cuando corresponda. No enviar fuentes privadas a otro modelo/servicio automáticamente.
