## Pasos

1. Crear npm workspaces, Astro SSR con adaptador Node y React, Node 22 y dependencias exactas. Elegir versiones compatibles comprobándolas, sin usar latest sin fijar el resultado.
2. Inicializar Supabase local y verificar PostgreSQL real. Registrar requisitos de Docker/CLI y configuración .env.example sin credenciales.
3. Crear check, build, test, test:db, test:e2e y verify con Vitest, SQL/pgTAP y Playwright; CI usa datos sintéticos. Los scripts fallan si faltan herramientas; el servidor muestra solo una página de estado del prototipo.

## Entrega concreta

Clon instalable, app local vacía y PostgreSQL local disponible, instrucciones y comandos reproducibles.

## Comprobación y cierre

- npm.cmd ci, npm.cmd run check y npm.cmd run build pasan en la base nueva.
- Cada runner ejecuta una comprobación mínima de entorno y devuelve error verificable ante requisito ausente; no simular una base con JSON.
- Escenarios: `V01`, `V02` en [VALIDACION](../VALIDACION.md).
- Registrar pruebas realmente realizadas y sus límites; el integrador cierra solo después de revisarlas.

## Entrada pendiente que no se debe inventar

Si falta Docker/CLI, documentar instalación necesaria; continuar código/configuración independiente, sin usar producción para probar.

## Informe de salida

Devolver archivos o parche y el informe según TRASPASO. Separar cambio local, commit, push, migración, servidor desplegado, frontend publicado y URL comprobada; usar «no realizado» cuando corresponda. No enviar fuentes privadas a otro modelo/servicio automáticamente.
