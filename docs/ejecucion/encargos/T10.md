# Encargo T10 — Incorporar la trayectoria temporal

**Estado:** completada
**Dependencias:** T08 y T05
**Responsable:** Desarrollo / Contenido

## Objetivo

Convertir las etapas temporales aprobadas en una cronología semántica, navegable y legible sin JavaScript. La cronología debe complementar el mapa y enlazar cada etapa con sus capacidades y casos relacionados cuando la conexión esté registrada.

## Fuente y alcance

- Se reutilizan las etapas editoriales ya aprobadas para el piloto: `1997–2002`, `Desde 2002` y `Desde 2004`.
- No se agregan fechas exactas, cierres de período, obras ni atribuciones nuevas.
- Los períodos con «Desde» se explican como abiertos en la versión actual.
- Las capacidades se vinculan mediante `stageIds` y los casos mediante `stageIds` de cada caso.

## Archivos permitidos

- `src/data/portfolio.ts`
- `src/pages/trayectoria/index.astro`
- `src/styles/global.css`
- `docs/ejecucion/encargos/T10.md`
- `docs/ejecucion/entregas/T10.md`
- `docs/ejecucion/entregas/T10-revision.md`
- `docs/ejecucion/TAREAS.md`

## Entregable

Una cronología HTML inicial con orden semántico, identificadores estables, períodos visibles, descripción de cada etapa, enlaces a capacidades y enlaces a casos relacionados.

## Criterios de cierre

1. La ruta `/trayectoria/` presenta una lista ordenada y legible sin JavaScript.
2. Los enlaces existentes a `trayectoria/#slug` siguen funcionando.
3. Cada etapa conserva su texto y período aprobado.
4. La cronología funciona con teclado, lectores de pantalla, móvil y escritorio.
5. La navegación temporal no reemplaza las páginas de casos ni el mapa.
6. `npm.cmd run check`, `npm.cmd run build`, las rutas HTTP locales y `git diff --check` pasan.
7. El informe distingue cambio local, commit, push, despliegue y URL comprobada.

## Traspaso

El ejecutor devuelve los archivos modificados y las pruebas realmente realizadas. El integrador actualiza el tablero y cierra T10. No se hace push, despliegue ni publicación durante este encargo.
